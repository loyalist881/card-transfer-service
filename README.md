# 💳 Card Transfer Service

REST API для выполнения переводов между банковскими картами.

Проект посвящён разработке backend-сервиса с особым вниманием к **транзакционности операций, конкурентному доступу к данным и предотвращению race condition / deadlock**.

## 🚀 Возможности

* 💳 Работа с банковскими картами
* 💸 Переводы между картами
* 💰 Проверка доступного баланса
* 🔄 Атомарное выполнение операций
* 🔒 Защита от конкурентного изменения баланса
* ⚡ Синхронизация доступа к общим ресурсам
* 🧪 Unit, integration и E2E тестирование
* 🐳 Запуск приложения в Docker

## 🔒 Работа с конкурентностью

Одной из основных задач проекта была корректная обработка нескольких одновременных переводов.

Для синхронизации доступа к картам используется `ReentrantLock`.

При работе с двумя картами блокировки выполняются в детерминированном порядке. Это позволяет избежать ситуации, когда два потока захватывают ресурсы в разном порядке и блокируют друг друга.

Упрощённо:

```text
Transfer A → B
Transfer B → A

        ↓

Одинаковый порядок получения Lock
        ↓

Снижение риска Deadlock
```

Таким образом, проект позволяет на практике разобраться с:

* race condition;
* thread safety;
* synchronization;
* locking;
* deadlock;
* atomicity операций.

## 💰 Транзакционность

Перевод между картами должен выполняться как единая операция:

```text
Проверка баланса
      ↓
Списание средств
      ↓
Зачисление средств
      ↓
Commit
```

Если операция не может быть полностью выполнена, изменения не должны оставаться в промежуточном состоянии.

## 🐳 Запуск

# Быстрый старт

Для быстрого запуска приложения вместе с FRONT-частью используется Docker Compose. 

Выполните команду для сборки и запуска контейнеров в фоновом режиме:
   ```bash
   docker-compose up -d --build
   ```

**Доступные порты после запуска:**
* REST: `http://localhost:5500`
* FRONT: `http://localhost:3000`

Для остановки приложения выполните:
```bash
docker-compose down
```

# Примеры запросов

Все суммы передаются в минимальных единицах валюты (копейках). Например, 100 000 = 1000.00 RUB.

### 1. Инициализация перевода
Метод принимает данные карт и сумму, проверяет их валидность, резервирует операцию и возвращает уникальный идентификатор.

* URL: `POST /transfer`
* Content-Type: `application/json`

**Пример запроса:**
```json
{
  "cardFromNumber": "1111222233334444",
  "cardFromValidTill": "12/26",
  "cardFromCVV": "123",
  "cardToNumber": "5555666677778888",
  "amount": {
    "value": 100000,
    "currency": "RUB"
  }
}
```

# Подтверждение перевода
Метод принимает идентификатор операции и код подтверждения. Рассчитывает комиссию, списывает средства и завершает перевод. В тестовой среде ожидается код `0000`.

* URL: `POST /confirmOperation`
* Content-Type: `application/json`

**Пример запроса:**
```json
{
  "operationId": "6c447b74-1b15-46e3-982d-86f345de07b6",
  "code": "0000"
}
```

# Логирование

В приложении реализовано логирование этапов перевода. Данные сохраняются в файл `logs/transfer-service.log`. Формат записи включает дату, время, карту списания, карту зачисления, сумму, комиссию и результат операции.

CVV-коды исключены из логирования (`@ToString.Exclude`) для соблюдения стандартов безопасности.
